# 任务编排

## 编排原则

- 每个接口/页面为一个可交付子任务，带输入、修改范围、验收标准与测试关注点。
- 依赖顺序：api → context → starter → 单测 → Liquibase → 接口测试；前端 service → 页面 → 路由/文案 → 构建 → UI 联调。
- 每完成一个子任务落盘产物并更新任务看板，避免上下文丢失。

## 生成方式

- 后端按“每接口一个子任务”串行生成，修改后立即编译。
- 前端按“每页面一个子任务”生成，修改后立即 lint/build。
- 测试按“先造数、再逐条 curl、后读日志”闭环执行。
