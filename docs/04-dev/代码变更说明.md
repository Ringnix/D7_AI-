# 代码变更说明

## 后端（backend-demo）

### 新增 api 模块

- `PurchaseRequestApi`：10 个方法（新增/详情/分页/修改/删除/提交/取消/撤回/审批/驳回）。
- DTO：`PurchaseRequestCreateDto`、`PurchaseRequestModifyDto`（继承 Create + version）、`PurchaseRequestItemDto`、`PurchaseRequestPageDto`（继承 `OrderPageParam`，current 从 1 起）、`PurchaseRequestVersionDto`、`PurchaseRequestReasonDto`、`PurchaseRequestApproveDto`。
- VO：`PurchaseRequestListVo`、`PurchaseRequestVo`、`PurchaseRequestItemVo`。
- 枚举：`PurchaseRequestStatus`（DRAFT/SUBMITTED/APPROVED/REJECTED/CANCELLED）。

### 领域层

- `PurchaseRequest`：主表实体，含状态、版本、取消/审批字段、`toListVo()`。
- `PurchaseRequestItem`：子表实体，`fromDto()` 计算明细金额。
- 仓储：分页 count/search、`updatePurchaseRequest(request, version)` 条件更新、明细按主表查询/删除。
- `PurchaseRequestDomainService`：
  - 新增：生成申请单号、保存主表、保存明细、计算总金额；
  - 修改/删除：仅草稿、版本校验、主子表同事务；
  - 提交/撤回/取消/审批/驳回：状态机 + 原因必填 + 版本条件更新；
  - 更新 0 行抛版本冲突。

### Web 层

- `PurchaseRequestController`：REST 端点与 Swagger 注解，X-Request-Id 写入 MDC。
- `OrderExceptionHandler` 扩展错误码映射：90000201/203/206 → 409，90000202 → 404，其余 400。

### 数据库

- `v1.3.0.xml`：建主表、子表、唯一约束、索引；Liquibase 记录表 `backend_demo__db_log`。

## 前端

- `src/service/purchase-request/*`：类型 + 10 个接口封装。
- `src/views/purchase-request/*`：列表、表单、详情、动作、状态标签、字段配置。
- 列表操作按状态渲染：草稿显示编辑/删除/提交/取消；待审批显示撤回/通过/驳回/取消；终态仅详情。
- 表单：主表 Form 校验 + 动态明细表格 + 实时合计；编辑时加载详情并携带 version。
- 错误提示：90000202/203/206/204/205 等映射为中文提示；删除确认使用 `deleteConfirm(content,false)` 避免误弹成功。
- 路由：`/purchase-request/list`；Vite 代理新增 `/api/purchase-requests` → 8081。

## 兼容性与风险

- 未改动订单模块与消费者服务；新增代码独立包/目录。
- `request_no` 由后端随机生成，唯一约束兜底；极端高并发下可能重复，已通过 DuplicateKeyException 转为 90000201。
- 未接权限/租户过滤（项目现有模块同样未启用），后续接入需在 Controller/仓储层补充。
