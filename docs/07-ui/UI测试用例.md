# UI 测试用例

> 环境：Vite dev server 3000 + mock 中台登录态（仅本地自测）+ 后端 8081 + MySQL。截图见 `07-ui/screenshots/`。

| 编号 | 场景 | 前置 | 步骤 | 预期 | 执行方式 |
| --- | --- | --- | --- | --- | --- |
| UI-01 | 列表渲染与分页 | 数据库有测试单据 | 打开 `/#/purchase-request/list` | 标题“采购申请单列表”、5 条数据、金额/状态/时间正确 | 自动化（Chrome CDP） |
| UI-02 | 操作按钮按状态显隐 | 存在待审批/已驳回单据 | 查看不同状态行的操作列 | 待审批：详情/取消/撤回/审批通过/审批驳回；已驳回：仅详情 | 自动化 |
| UI-03 | 详情弹框 | 存在待审批单据 | 点击第一行“详情” | 展示主表、状态、金额、采购明细；可关闭 | 自动化 |
| UI-04 | 新增表单弹框 | 列表页 | 点击“新增采购申请单” | 弹框含标题/申请人/部门/备注、明细表格 1 行、合计 ¥0.00 | 自动化 |
| UI-05 | 取消原因弹框 | 待审批单据 | 点击“取消” | 弹框含“取消原因”文本域、取消/确定按钮 | 自动化 |
| UI-06 | 新增保存 | 列表页 | 填主表 + 明细 → 确定 | 提示创建成功，新行出现在列表 | 人工清单（见未验证项） |
| UI-07 | 编辑保存 | 草稿单据 | 打开编辑 → 修改 → 确定 | 提示修改成功，版本递增 | 人工清单 |
| UI-08 | 提交/撤回/审批/驳回 | 对应状态单据 | 点击操作并确认/填写原因 | 提示成功，状态与按钮变化 | 人工清单（接口已覆盖） |
| UI-09 | 原因必填 | 取消/驳回弹框 | 原因留空点确定 | 提示“原因不能为空”，不调用接口 | 人工清单 |
| UI-10 | 删除草稿 | 草稿单据 | 删除并确认 | 提示删除成功，行消失 | 人工清单（接口已覆盖） |
