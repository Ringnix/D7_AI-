# 采购申请单菜单与访问地址（含 uc 包接入）

## 1. 已引入公司私库 uc 包

已通过公司 Nexus npm 私库（registry 已配置在用户级 `.npmrc`）安装：

```text
cyberway-mp-uc-web@1.23.0   （用户中心，moduleAlias: mp-uc）
```

已在 `package.json` 增加依赖并新增启动脚本：

```json
"uc:serve": "node scripts/serve-uc.mjs"
```

`scripts/serve-uc.mjs` 会把 uc 包 `dist` 以本地静态服务方式启动，并把其 `env.json` 改写到当前开发环境地址（不修改 node_modules 内文件，重装依赖后仍可用）。

## 2. 启动用户中心（用于配置菜单/资源/角色）

```powershell
cd C:\Users\CyberUser\Desktop\cyberway-mp-frontend-template-release-1.23.0
yarn uc:serve
```

访问：

```text
http://127.0.0.1:3001/
```

用你的中台账号登录后，在用户中心里进入「应用/资源/菜单/权限角色」相关页面，为应用 `web-order-zchengli` 添加：

- 目录资源：`purchase-request`（采购申请单）
- 页面资源：`purchase-request-list`（采购申请单列表）
- 把资源授权给你的角色，刷新前端后菜单出现。

> 说明：`cyberway-mp-uc-web` 是用户中心微前端应用，不是“在业务前端代码里挂菜单”的 SDK；菜单仍然由平台资源授权决定。如果账号在用户中心里也没有资源/角色授权权限，则只能走下面的直连 URL，或请导师/平台管理员授权。

## 3. 前端访问 URL

### 本地开发

```text
http://localhost:3000/#/purchase-request/list
```

已用真实浏览器验证：登录态下页面正常渲染「采购申请单列表」，加载到真实接口数据（见 `07-ui/UI测试结果.md`、`07-ui/screenshots/ui-list.png`）。

### 前端容器部署（nginx 监听 6767）

```text
http://<前端部署主机IP>:6767/#/purchase-request/list
```

部署时需在 nginx 反代 `/api/purchase-requests` 到后端 A 的 8081，否则页面能打开但列表 404/502。

## 4. 当前运行状态

- 后端 A：8081，已用含采购申请单模块的最新 jar（`deploy/backend-demo-server.jar`）重启；
- 前端 dev：3000 运行中；
- 用户中心 uc：3001 运行中（`yarn uc:serve`）。

## 5. 如果 uc 配置仍然失败

直接使用第 3 节 URL 即可访问页面；菜单配置问题不阻塞页面功能验收。
