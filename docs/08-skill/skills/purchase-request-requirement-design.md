# 采购申请单需求/设计生成 Skill

## 触发条件

- 新单据模块包含主表 + 明细、保存/提交/审批/驳回/取消/撤回、乐观锁。
- 已有项目采用 DDD 分层（api/context/starter）与 MyBatis + Liquibase。

## 输入

- 需求基线（功能点、状态流转、原因必填、并发要求）
- 现有同类模块（如订单）的分层、分页 DTO、前端组件与字段规范

## 核心判断

1. 先读现有模块与数据库记录表，再设计，禁止凭空造字段。
2. 审批只记录状态，不引入工作流引擎。
3. 状态机穷举合法流转；非法流转统一 409/业务码。
4. 主表必须有 version，所有写操作条件更新。
5. 需求歧义列“待确认事项”，采用最小假设继续。

## 工作流程

1. 盘点现有模块 → 2. 按需求模板输出需求文档 → 3. ER 图/表结构 → 4. 接口清单 → 5. 改动清单与测试关注点 → 6. AI 自评审记录。

## 产出

- `01-requirement/采购申请单需求文档.md`
- `01-requirement/需求澄清与待确认.md`
- `02-design/技术设计.md`、`ER图.md`、`表结构设计.md`、`接口清单.md`

## 验证方法

- 状态流转无死链；每条流转有接口/用例对应；
- 表字段能支撑所有页面展示与状态；
- DDL 只走 Liquibase，记录表名与项目一致。

## 不适用范围

- 复杂 BPM 审批流、跨系统流程编排；
- 需要权限码/租户过滤落地的场景（需补充设计）。
