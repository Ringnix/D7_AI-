## 1. 前言

### 1.1 读者对象

- 开发人员：作为接口、数据模型、状态机实现依据
- 测试人员：作为接口与页面验收依据
- 导师/评审人：作为需求完整性与假设确认依据

### 1.2 方案范围

- 采购申请单主表 + 明细子表（一对多）
- 单据保存草稿、提交、撤回、取消、审批通过、审批驳回
- 列表分页/筛选、详情查看
- 乐观锁并发控制
- 不接入中台审批流，仅记录状态与审批信息

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 采购申请单 | 员工发起采购需求的单据，含主表信息与多条采购明细 |
| 待审批 | 已提交、等待审批的状态 |
| 撤回 | 待审批单据由申请人收回，回到草稿 |
| 取消 | 草稿或待审批单据终止流程，必须记录取消原因 |
| 驳回 | 审批人不同意，必须记录驳回原因 |

## 2. 业务概述

### 2.1 场景背景

员工需要采购物品时填写采购申请单，提交后由审批人审批；申请人在审批前可撤回，草稿可修改或删除；单据终止需记录原因，便于追溯。

### 2.2 业务目标

1. 规范采购申请流程与状态流转，避免单据状态混乱。
2. 主子表结构化记录采购内容与金额。
3. 关键动作留痕（取消原因、驳回原因、审批人、审批时间），可追溯。
4. 支持多人同时操作，避免覆盖更新。

### 2.3 流程概述

```
保存草稿(DRAFT) → 提交 → 待审批(SUBMITTED) → 审批通过(APPROVED)
                                   ↘ 审批驳回(REJECTED)
草稿/待审批 → 取消(CANCELLED，原因必填)
待审批 → 撤回 → 草稿
```

### 2.4 角色与职责

| 角色 | 职责 | 关键权限 |
| --- | --- | --- |
| 申请人 | 创建、编辑、删除草稿，提交、撤回、取消 | 仅草稿可编辑/删除；草稿/待审批可取消 |
| 审批人 | 对已提交单据审批通过或驳回 | 仅待审批可审批 |
| 系统 | 记录状态、原因、审批信息与版本号 | 不改变业务规则 |

> 本次实训不接入中台用户/角色权限，按钮按状态显隐；权限码接入列为后续项。

## 4. 列表页

### 4.1 查询条件

| 字段 | 控件 | 默认值 | 查询方式 |
| --- | --- | --- | --- |
| 申请单号 | 文本 | 无 | 模糊 |
| 标题 | 文本 | 无 | 模糊 |
| 状态 | 下拉 | 无 | 精确 |

### 4.2 列表字段

申请单号、标题、申请人、申请部门、申请金额、状态、创建时间、操作列。

### 4.3 状态与可执行操作

| 状态 | 可执行操作 |
| --- | --- |
| 草稿 DRAFT | 详情、编辑、删除、提交、取消 |
| 待审批 SUBMITTED | 详情、撤回、审批通过、审批驳回、取消 |
| 已通过 APPROVED | 详情 |
| 已驳回 REJECTED | 详情 |
| 已取消 CANCELLED | 详情 |

## 5. 新增/编辑页（弹框）

- 主表字段：标题（必填，≤100）、申请人（必填，≤100）、申请部门（必填，≤100）、备注（≤500）。
- 明细：至少一条；字段为物品名称（必填）、规格型号、单位、数量（>0，两位小数）、单价（>0，两位小数）。
- 金额：明细金额 = 数量 × 单价（后端计算），申请总金额 = 各明细金额之和。
- 编辑：仅草稿；携带版本号，版本不一致返回冲突提示。
- 保存成功提示；新增后返回第一页，编辑后保持当前页。

## 6. 详情页（弹框）

展示主表信息、状态、金额、备注、创建/修改时间、取消原因与时间、审批人/时间/意见、明细表格。

## 7. 审批/动作弹框

| 动作 | 是否必填原因 | 记录内容 |
| --- | --- | --- |
| 取消 | 必填 | 取消原因、取消时间、状态 CANCELLED |
| 驳回 | 必填 | 驳回原因、审批人、审批时间、状态 REJECTED |
| 审批通过 | 选填审批意见 | 审批人、审批时间、意见、状态 APPROVED |

## 8. 异常与提示

| 场景 | 返回 | 页面提示 |
| --- | --- | --- |
| 单据不存在 | 404 / 90000202 | 采购申请单不存在或已被删除 |
| 状态不允许 | 409 / 90000203 | 当前状态不允许该操作 |
| 取消原因缺失 | 400 / 90000204 | 取消原因不能为空 |
| 驳回原因缺失 | 400 / 90000205 | 驳回原因不能为空 |
| 版本冲突 | 409 / 90000206 | 数据已被他人修改，请刷新后重试 |
| 参数校验失败 | 400 | 表单/后端校验提示 |

## 9. 并发控制

- 主表 `version` 字段，初始 0，每次成功更新 +1。
- 所有写操作（修改/提交/取消/撤回/审批/驳回）携带前端持有的版本号，SQL 条件 `id = ? and version = ?`。
- 更新影响行数为 0 时返回版本冲突（90000206），前端提示刷新。

## 10. 测试关注点

- 主子表保存/查询/删除一致性
- 状态机全路径与非法流转
- 取消/驳回原因必填
- 乐观锁冲突（含并发提交）
- 分页字段与筛选条件
- 参数校验（标题、明细、数量、单价）
- 前端按钮随状态显隐、金额合计
