# 日志排查记录

## 执行前日志自检

- local profile 默认只输出控制台；启动时将 stdout/stderr 重定向到：
  - `C:\Users\CyberUser\Desktop\backend-demo\logs\api-server.log`
  - `C:\Users\CyberUser\Desktop\backend-demo\logs\api-error.log`
- 启动后确认 `Tomcat started on port 8081`、Liquibase `Command execution complete`。

## 失败排查

两轮执行均无 FAIL，无需要修复的接口失败。

| 现象 | 排查 | 结论 |
| --- | --- | --- |
| 第一轮日志 `requestId=d7-$CaseId-$runId` 未插值 | 检查测试脚本 header 使用单引号 | 测试脚本问题，改为双引号插值后重跑；非业务代码 |
| 负向用例出现 WARN `BaseI18nException` | 对照 pitfalls E10 | 预期行为，不是故障 |
| 日志中未出现 ERROR 行 | `Select-String -Pattern '\[ERROR\]'` 计数为 0 | 无未处理异常 |

## 证据

- `Select-String -Path logs\api-server.log -Pattern "采购申请单操作 requestId="` 可看到每条操作日志；
- 失败用例 C30 的 WARN 记录：`requestId=d7-C30-20261124-145257 operation=delete ... failure error=BaseI18nException`，与“非草稿不可删除”预期一致。

## 踩坑沉淀

1. MySQL CLI 的 `source` 无法打开含中文的路径：将 seed.sql 复制到 ASCII 临时目录后执行。
2. 含中文 JSON 用 UTF-8 无 BOM 文件 + `--data-binary @file`，不使用内联 JSON。
3. Windows 用 `curl.exe`，不依赖 PowerShell 别名。
